01 / Match the problem

Start with the output you need.

One good solution

Keep linear structure for LP/MIP. Use SQP for a small smooth NLP with derivatives. Use fcmaes for a black-box simulation, multimodality or nonsmoothness.

A Pareto front

Use MODE for black boxes. Structured linear or smooth models can use a sequence of scalarized solves; independently filter and check the candidates.

Diverse good solutions

Use MAP-Elites or the Diversifier in fcmaes. Define behavior descriptors that capture the diversity your application actually needs.

Need a large sparse NLP, conic solver, dedicated routing/CP solver or certified global MINLP? The shared guide explains when to use tools outside this ecosystem.

03 / Run and inspect

A shared job layer for a shell or MCP.

On Linux with Rust 1.88 or newer, start from one worker repository. Its locked build includes a compatible runner and MCP server. The runnable tutorial initializes a node and exercises example jobs:

git clone https://github.com/dietmarwo/fcmaes-rust
cd fcmaes-rust
cargo build --release --locked -p optimization-runner -p fcmaes-job-worker
cargo build --release --locked -p fcmaes-job-worker --example custom_worker
python3 tutorials/job-api/run.py --root /tmp/fcmaes-job-tutorial

Use a fresh tutorial directory. Read the fcmaes job tutorial for prerequisites, resource settings and output inspection. Equivalent tutorials: LP/MIP and SQP.

Connect an agent

Configure its MCP client to launch optimization-mcp --root /absolute/path/to/node over stdio, using the absolute executable path. The owner must initialize the node and register workers first.

Then call get_guide, describe_node and describe_worker. Use the returned schemas and examples to validate and submit a job.

Budget the CPU explicitly

Discover the host and worker limits before choosing outer workers and inner threads. The runner accounts for outer_workers × inner_threads ≤ cpu_slots; this is cooperative admission, not physical CPU isolation.

A many-core host often benefits from concurrent trials or starts. Eight inner threads are not automatically the best choice for one solve.

LP/MIP jobs accept model data. A new nonlinear application needs a model registered in a Rust worker; jobs do not carry arbitrary Python callbacks or shell commands. See the shared guide for setup, model registration, limitations and result checks.

04 / Check the evidence

Integration is evidence. Ranking needs a benchmark.

OptunaHub's FastCmaesSampler, by Jacob Pfeil, integrates fcmaes CMA-ES into Optuna. It is an attributable third-party integration of fast-cma-es; it does not validate the other four projects or establish a performance ranking.

The repositories provide their own tests, benchmark harnesses and reproduction instructions. Compare solver versions on the same models, tolerances, CPU allocations and budgets, include failures and repeat seeds. Report wall time and total CPU effort separately.

A comparison with other open-source optimization systems for agents sets these projects beside GEMSEO, libEnsemble, Optees, Optuna, BO-MCP, cuOpt, Frontier and Dakota. It reviews documentation and source and is published by the maintainer, so it is not an independent evaluation.
